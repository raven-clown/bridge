# bridge v0.1 part 1: inbox, thread and triage

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Go binary that discovers the user's repositories, builds one ranked inbox of pull requests, issues, review requests, mentions and pushed branches across all of them, opens any item as a thread with reply, and applies labels, milestones, assignees, project moves and state changes from the terminal.

**Architecture:** Library packages at the module root hold the domain (`forge`, `config`, `store`, `auth`, `discover`, `inbox`, `thread`, `triage`) and never touch the terminal. `forge/github` implements the `forge.Forge` interface with go-github for REST and githubv4 for GraphQL. `internal/tui` is a bubbletea program with one model per view. `cmd/bridge` wires config, auth and the forge, and offers the same operations as subcommands with `--json`.

**Tech Stack:** Go 1.26, charmbracelet/bubbletea + bubbles + lipgloss, google/go-github/v68, shurcooL/githubv4, go-git/go-git/v5, zalando/go-keyring, spf13/cobra, gopkg.in/yaml.v3, charmbracelet/x/exp/teatest, goreleaser.

**Spec:** `docs/superpowers/specs/2026-11-21-bridge-design.md`

## Global Constraints

- Module path `github.com/raven-clown/bridge`, Go 1.26 or newer, Apache-2.0.
- One static binary. No `exec` of `git`, `gh` or any other program anywhere in the code.
- Windows is a first-class target: every test passes on `windows-latest`; paths go through `filepath`; config accepts both `D:/workspace` and `D:\workspace`.
- No telemetry, no network call except to the configured forge host.
- The token never appears in config files, logs, error messages or test fixtures.
- Library packages contain no `fmt.Print*`, no `os.Stdout` and no bubbletea import.
- Default merge title `{title} (#{number})`, default merge body empty (ship is a later plan, but the config shape ships now).
- Config path: `%APPDATA%\bridge\config.yaml` on Windows, `~/.config/bridge/config.yaml` elsewhere. State path: `%LOCALAPPDATA%\bridge\` on Windows, `~/.local/state/bridge/` elsewhere. Env override `BRIDGE_<KEY>` with `__` between nested keys.
- Refresh timer default 90 seconds. Discovery depth default 2.
- Docs, comments and commit messages: plain English, Conventional Commits, no em-dashes, no mention of code generation tools. No `Co-Authored-By` or similar trailers.
- Tests with every task, table-driven where there is a table, no network, no bare `time.Sleep`.

## Review Focus

1. A repository whose remote is not on github.com (GitLab, a bare path, no remote at all) must be listed by discovery as unmapped and skipped by refresh without an error row. Test in Task 6.
2. A token without `read:project` makes GitHub return a GraphQL error with type `FORBIDDEN` on project fields. The inbox must still load, and the triage panel must say "projects need the read:project scope" instead of showing an empty list. Test in Task 10.
3. GitHub search returns at most 100 items per page and 1000 in total. Lists must paginate on `hasNextPage` and, at 1000, mark the result as truncated so the inbox shows a banner rather than a silent cut. Test in Task 9.
4. A `403` with `Retry-After` or `x-ratelimit-remaining: 0` (secondary rate limit) must surface as a problem row with the retry time, with the cached inbox still on screen. Test in Task 8 (refresh) and Task 9 (header parsing).
5. Replying to a comment whose thread was deleted or locked returns `404` or `422`. The reply must stay in the local draft and the error must be shown next to the compose box, not lost. Test in Task 11 and Task 14.
